# PDF line highlighting regression

Run from the repository root while the frontend is serving:

```bash
E2E_BASE_URL=http://127.0.0.1:3013 ./scripts/run_whisper_highlight_tests.sh
```

The runner verifies the fixture, runs 15 backend checks, then eight browser
checks. Locally it uses `/home/mrx/.local/venv/bin/python`. CI sets `PYTHON_BIN`
to its installed Python. No new virtual environment is created.

## What a failure means

The tests use actual Whisper paper pages 7, 8 and 11. They cover the Welsh
paragraph, `(CY)`, `X→en`, `10×`, `We caution`, and `Improvements in WER`.
For each passage they check that:

- The parser preserves the fixed physical line, its neighbors and word boxes.
- The clicked PDF span receives the active highlight and speech starts there.
- The highlighted text matches the expected line, with every active rectangle
  inside the independently measured PDF.js row, within two CSS pixels.
- Exactly one visual line is highlighted and the text layer has not scrolled
  internally relative to its canvas.
- Real Audio playback progresses. Seeking near its end lets the native `ended`
  event advance to the immediate next line. No next-line click substitutes for
  testing the playback queue.
- Zoom changes keep the highlight on the same physical line.

Each affected passage is a separate named browser test. Failed tests retain a
screenshot and Playwright trace. Successful checks also save clicked-line and
next-line screenshots under `_scratch/line-highlight-regression`.

## Proving that the assertions catch corruption

A negative-control browser test loads the original stale Docling paragraph
payload. Clicking `amount of Welsh` produces five highlighted physical lines.
The same assertion used for healthy data rejects it. The test then removes the
active highlight and moves it to the actual adjacent row in the DOM. Both
states must be rejected. Even assigning the correct words to the wrong row's
observation fails the geometry check.

The frozen expectations are not regenerated by normal tests. They contain
reviewed line text and saved word geometry from the restored extraction. Browser
row geometry is measured independently from the rendered PDF, rather than
copied from the parser under test. Do not update the expectations just to silence
a failure.

## Fixtures and scope

`e2e/fixtures/whisper-pages-7-8-11.pdf` retains the three original pages at their
original indices, with blank pages elsewhere. The original PDF SHA-256 and the
fixture SHA-256 are recorded in `whisper-expectations.json`. The source is
*Robust Speech Recognition via Large-Scale Weak Supervision*. Regenerating the
PDF with `scripts/build_whisper_highlight_fixture.py --source-pdf <original>`
requires pypdf; normal verification does not.

The browser uses the real Next.js build, PDF.js text layer, narration queue and
highlight code. It runs the real PDFParserService against the frozen PDF at
runtime. API routes, authentication and speech responses are mocked. Audio is a
fixed silent WAV played by the real HTMLAudioElement. These tests need no model
or database and do not scan existing library records for stale extraction.

`.github/workflows/validate.yml` runs the backend tests, the alignment offset
self-checks and these browser tests for pushes and pull requests.
