1. Executive summary

OpenNoteBox is a self-hosted, NotebookLM-style document reader (FastAPI + Postgres + Celery backend, Next.js frontend, Piper TTS service, Traefik HTTPS entry point). Overall the codebase is in good shape: all 189 backend tests pass, the frontend type-checks, lints, and builds clean, the security posture is notably strong for a self-hosted app, and the code carries unusually good explanatory comments.

The audit found no critical issues, but three high-priority items, all related to git hygiene around the in-flight HybridRAG / knowledge-graph feature:

  • CI would currently fail if the working tree were pushed: 36 ruff errors, 9 of them in the new (untracked) KG files and 27 in already-tracked files.
  • A stray 225 KB SQLite artifact (open-notebox/file:memory:testdb, produced by the test suite) sits untracked and unignored at the repo top level. A git add -A would commit a binary test database.
  • The same uncommitted KG feature exists in two places: this working tree and the open-notebox-hybrid-rag worktree, whose branch is 40 commits behind and whose open-notebox/ is a full nested copy. The two copies have already started to drift (chat.py, chat_engine.py differ).

Everything else is medium/low severity: 15 stale gnhf/* branches all pointing at one commit, 3 high-severity npm advisories (dev-only PostCSS chain, fix requires a Next 16 breaking upgrade), zero frontend tests, the KG build running LLM calls in the web process without the shared LLM semaphore, and two dangling gitlinks (open-notebook, open-webui) with no .gitmodules that will break clones.

3. Findings by severity

HIGH  CI gate (ruff) is red: 36 lint errors

The GitHub Actions backend job runs ruff check .. It currently finds 36 errors: 9 in the new untracked KG files (knowledge_graph.py 3, kg_retrieval.py 3, kg_builder.py 2, hybrid_rag.py 1), plus 27 in already-tracked code (metrics.py, bookmarks.py, db_monitor.py, task modules, tests). Nearly all are F401 unused imports / F841 unused variables / one E402 / one F541.

Fix: cd backend && ruff check . --fix (32 auto-fixed) then hand-resolve the 4 F841s (e.g. unused doc in knowledge_graph.py:45, unused stats in metrics.py:207) and move the E402 import in metrics.py:261.
HIGH  Unignored test artifact will be committed

open-notebox/file:memory:testdb (225 KB SQLite file) is untracked and not covered by any gitignore rule: the repo-root .gitignore only lists problem/ and open-notebox-hybrid-rag/; the app-level .gitignore rule backend/file:memory:testdb covers the sibling copy in backend/ only. The file is produced by tests/conftest.py, which uses sqlite:///file:memory:testdb?mode=memory&cache=shared - a shared-cache in-memory URL that materializes a real file on disk when any connection writes (a second copy, 266 KB, already exists in backend/ from today's test run).

Fix: delete both files, and either add file:memory:testdb to open-notebox/.gitignore (any depth) or switch conftest to StaticPool + sqlite:///:memory: so no file is ever created.
HIGH  Same uncommitted feature duplicated across two worktrees, already drifting

The HybridRAG/KG feature (8 untracked files + 12 modified) exists byte-identical in both the main tree and the open-notebox-hybrid-rag worktree's nested open-notebox/ copy. However the worktree's chat.py and chat_engine.py already differ, and the feature/hybrid-rag branch (f3ab604) is an ancestor of feature/open-tasks (40 commits behind, 0 ahead). Continuing edits in either place risks forking the feature.

Fix: pick one home for the feature (recommend the main tree on feature/open-tasks), commit it there, then git worktree remove the stale worktree or re-point its branch at the commit.
MED  15 stale gnhf/* branches

All 15 gnhf/use-the-blueprint-an-* branches point at the single commit 2bdc183 ("base"), 67 commits behind. They contain no unique work and are dead weight in branch lists. master and feature/ui-overhaul also sit at the same tip (48147a4), 7 commits behind feature/open-tasks.

Fix: delete the 15 gnhf branches (git branch -D gnhf/...); decide whether feature/ui-overhaul is still live; fast-forward master when feature/open-tasks lands.
MED  KG build runs LLM calls in the web process, unsynchronized

POST /api/kg/documents/{id}/build uses FastAPI BackgroundTasks (in-process, dies with the web worker, no retry/queue) instead of Celery like every other long job (podcasts, summaries, flashcards). kg_builder.py calls the LLM directly via ChatOpenAI per chunk (2 calls/chunk) without the shared llm_semaphore, so a KG build on a 200-page doc can OOM or starve a shared single-GPU Ollama. It also re-queries the full entity table on every chunk (entity_count = len(db.query(KgEntity)...all())), an O(n²) query pattern. There are also no tests for any KG code.

Fix: move the build into a Celery task (the pattern already exists in app/tasks/), wrap model calls in llm_semaphore, count entities once at the end, and add at least a unit test for _split_kg_chunks / triplet JSON parsing.
MED  hybrid_rag couples to private APIs and double-counts a metric

hybrid_rag.py reaches into chat_engine.chat_engine._model() and _rewrite_query() (private members) and imports them at call time. When rag_mode is hybrid/graph, chat_engine.answer() increments m.rag_requests and then answer_hybrid() increments it again, skewing the /api/metrics RAG counter 2x for every hybrid request. The generic except Exception: fallback to standard also silently degrades errors into slower standard RAG with only a log line.

Fix: promote the needed helpers to public methods (or a shared module), increment the counter in exactly one place, and fail the request (502/503) when the requested mode is unavailable rather than silently switching modes.
MED  npm audit: 3 high-severity advisories (dev tooling chain)

npm audit reports 3 high-severity PostCSS advisories (XSS via unescaped </style>; arbitrary .map/file read via sourceMappingURL) in a nested copy under next@14. PostCSS is a dev/build-time dependency, so runtime exposure is low, but the build pipeline is the attack surface in CI. The fix requires next@16 (breaking).

Fix: schedule a Next 14 → 16 upgrade (React 19 + App Router changes); until then the risk is confined to trusted-source builds.
MED  Zero frontend tests

The backend has 189 passing tests across 9 suites; the frontend has 0 test files. The pure-logic modules (narrationFilter.ts, sentences.ts, passwordStrength.ts, textAlign.ts, uid.ts) and the recently hand-patched PdfViewer cache/versioning logic are exactly what regression tests should cover. CI only runs tsc + eslint + build, which all pass but prove compilation, not behavior.

Fix: add a Vitest suite for the lib/ modules (hours, not days) and wire it into CI's frontend job.
MED  Dangling gitlinks break fresh clones

open-notebook (c4749ad) and open-webui (ecd48e2) are committed as gitlink entries (mode 160000) but the repo has no .gitmodules. A fresh clone of deep_read gets empty directories for both, with no way to know which upstream repos to fill them with. They appear to be reference material (500 MB / 22 MB locally).

Fix: either add a real .gitmodules with origins, or remove the gitlinks (git rm --cached open-notebook open-webui) and gitignore the directories.
LOW  Config defaults that favor LAN convenience over lock-down
  • cors_allow_private_networks defaults to True (private-network origin regex) - well documented as a tradeoff, but must be flipped on any publicly reachable instance.
  • allow_registration defaults to True - anyone reaching the app can create an account until an operator disables it.
  • Postgres/Redis/API/frontend/TTS all bind to 127.0.0.1 in compose (good), with default opennotebox/opennotebox DB credentials (acceptable loopback-only, documented).
  • vllm_api_key defaults to the literal "EMPTY" (Ollama convention; harmless).
LOW  Disk & artifact housekeeping
  • data/ is 1.9 GB and root-owned (containers ran as root): tts-cache 856 MB across 1,351 files (LRU eviction exists, cap 2 GiB), podcasts 435 MB, extracted 431 MB, uploads 208 MB; exports/ 244 MB.
  • Two stray file:memory:testdb binaries on disk (225 KB / 266 KB) - safe to delete.
  • problem/ (712 KB scratch), _research/ (43 MB) are gitignored research dirs; fine to keep, worth knowing.
  • Unused-looking deps: langgraph and tiktoken are declared in pyproject.toml but never imported in app/ (ai-prompter is used in prompts.py).
  • KgExtractionState declares unique=True on the column and a separate UniqueConstraint on the same column (redundant, not harmful).
GOOD  Notable strengths
  • Full backend test coverage of the API surface; all green.
  • Strong auth: startup refusal on placeholder JWT secrets, bcrypt (async-wrapped), access/refresh tokens carry a type claim so refresh tokens can't be replayed as bearer, WebSocket requires a JWT via subprotocol or query param, every document-scoped endpoint re-checks user_id ownership (including all new KG endpoints).
  • Uploads: extension whitelist, size cap, sanitized per-user filenames, per-user directories.
  • Network surface minimal: only 443 (Traefik) is exposed by default; everything else is loopback-bound; HTTPS-only public path; IPv6 publish explicitly prevented.
  • Migration chain is clean: 6 revisions, single head, KG migration (f4a2b8c1d3e7) verified to chain off e7c3a91b4d20.
  • Unusually good comments documenting why (pool sizing, CORS rationale, driver choice, port publishing) - a real maintainability asset.
  • Uncommitted frontend fixes are solid and test-worthy: functional-state updates in admin page, PDF.js doc destroy on unmount, page-text cache versioning against re-parse, blob-URL revocation in voice preview, state-during-render fix in ModelPicker.

8. Security audit

Credible

  • Auth: HS256 JWT with expiry; startup RuntimeError if JWT_SECRET is a placeholder or <16 chars (checked against a blocklist); local .env has a proper 64-char secret. Bcrypt with cost from gensalt(), wrapped in asyncio.to_thread so the event loop never blocks on hashing. Refresh tokens are type-tagged and rejected as bearer.
  • Authorization: per-user document ownership re-checked in every endpoint, including all new KG routes and downloads; admin endpoints behind require_admin; WebSocket /ws/progress authenticates via subprotocol header or query token and closes (4001) without a valid user.
  • Uploads/downloads: extension whitelist + size cap; stored names sanitized via _stored_filename under uploads/<user_id>/; download endpoint serves doc.file_path only after the ownership check (no user-controlled path component).
  • Network: single public listener (Traefik 443, IPv4-only to avoid accidental IPv6 publish); Postgres/Redis/API/frontend/TTS loopback-bound; compose hard-codes 127.0.0.1 for the plaintext loopback entry.
  • Secrets: none tracked; .env, certs/ gitignored; CA key is 0600; .env.example carries no real values.
  • Injection: SQLAlchemy parameterized queries throughout; the one raw SQL (SELECT ... FROM extracted_text) uses bound params; KG entity-name filter uses ilike with a bound param (pattern wildcards from input are a cosmetic concern only, no injection).

Residual / watch items

  • CORS_ALLOW_PRIVATE_NETWORKS=true default admits any private-network origin (documented, deliberate for LAN phones; must be disabled + exact origins on public instances).
  • allow_registration=true default: open sign-up until an operator flips it.
  • Default DB credentials on loopback Postgres (acceptable per the compose comment; change if the port is ever exposed).
  • Next 14 / PostCSS dev-chain advisories (3 high) - build-time only.
  • data/ root ownership means host-side maintenance (backups, pruning) needs sudo.
